# Weekly improve report — 2026-08-17 06:44

Claude proposed **6** change(s).

## ✅ Applied (in this PR)
- **Fix Hanterad skip when SMS fails — booking marked as seen but never confirmed** (`agent.py`, impact: high) — In agent.py, when SMS fails the booking_id is added to seen_ids and 'continue' skips Hanterad. On the next run the booking is treated as already handled ('Already handled: ... skipping') so it is silently dropped forever with no SMS and no Hanterad. The booking should NOT be added to seen_ids on SMS failure so it can be retried.
- **Persist seen_ids even when SMS fails for some bookings** (`agent.py`, impact: medium) — save_seen_ids(seen_ids) is only reached at the end of the loop. If an exception occurs mid-loop, successfully-notified booking IDs are lost and will be re-notified. The run history shows repeated runs with bookings_found staying constant and sms_sent=0, consistent with a booking that is stuck. Saving incrementally protects against duplicate SMS.
- **Förfrågan bookings never trigger parts_agent as documented** (`agent.py`, impact: high) — SKILL.md and agent.py docstring state that Förfrågan bookings should launch parts_agent.py to build a quote. In agent.py there is no call to parts_agent anywhere — Förfrågan bookings only get an SMS and a warning. This is a documented behavior that is not implemented. Marking auto_apply false because parts_agent.py is not present and behavior change requires review.
- **Login wait_for_url predicate can never fire on same-URL redirect** (`portal_scraper.py`, impact: low) — In portal_scraper.fetch_bookings the wait_for_url lambda requires 'promeisterportal.com' in url AND url != PORTAL_LOGIN_URL. If the portal keeps the same path after auth (SPA), the predicate times out silently (caught by except PWTimeout: pass). This adds up to 15s of dead wait every run. Reducing the timeout and relying on networkidle is safer, but keep behavior — lower the timeout to reduce wasted time.
- **qty column index assumption may misread parts quantity** (`portal_scraper.py`, impact: low) — In _extract_specification, qty is read from cells[3] unconditionally: 'qty = cells[3].inner_text().strip() if len(cells) > 3 else ""'. Different table layouts put quantity in different columns, and SMS shows 'x' + qty. If cells[3] is a price/unit column this produces wrong quantities in the SMS. This is a low-risk defensive fix to only treat purely-numeric small values as qty.
- **mark_booking_handled has no cookie dismissal before Hanterad locator, but relies on it** (`portal_scraper.py`, impact: low) — SKILL.md notes 'Cookie popup must be dismissed before any clicks work'. In mark_booking_handled _dismiss_cookies is called after goto, which is correct, but there is no re-dismiss after the wait_for_timeout(1000) where a late cookie banner could reappear on SPA re-render, blocking the native Hanterad click. Add a second dismiss right before locating the button.

- **Investigate 3+ weeks of zero bookings found** (`portal_scraper.py`, impact: high) — Run history shows bookings_found=0 on every single run since 2026-09-17 (over 2 weeks). Before that bookings were regularly found (1-3 per run). This strongly suggests the Nya tab detection or booking link collection broke — likely the portal UI changed. The _collect_booking_links relies on a[href*='BookingInfo'] which may no longer match. Need diagnostics: when 0 links found, the code already screenshots to logs/no_bookings.png and logs first 500 chars of body — but we cannot see those. Add richer logging of anchor hrefs and candidate link patterns to diagnose.
- **email_trigger module may silently skip all booking runs** (`agent.py`, impact: medium) — agent.py imports should_run from email_trigger and exits early if it returns False. Given 2+ weeks of bookings_found=0 with no 'skipped' entries in run history, the trigger gate is passing but bookings are not found — OR skipped runs aren't being logged distinctly. The structured history never shows skipped:true, meaning should_run always returns True in these runs, so the problem is downstream in scraping, not the trigger. No code change here, but confirms focus belongs on link collection (proposal 1). No safe automatic fix; flagging for manual review.
- **Nya tab click has no verification or fallback selector** (`portal_scraper.py`, impact: high) — The Nya tab is clicked via a broad JS loop matching text /^Nya\b/ with length < 15. If the portal renamed the tab, added a count suffix making it >15 chars, or changed structure, the click silently returns 'not found' and processing continues with whatever tab is active (possibly an empty one). This is a prime suspect for the 2-week zero-booking streak. Log the result more prominently and fall back to navigating to a Nya-specific URL if available.
- **Booking type default to 'Bokning' risks false Hanterad confirmation** (`portal_scraper.py`, impact: medium) — _detect_booking_type defaults to 'Bokning' whenever 'förfrågan' and 'offert' are not found in text, and never positively verifies the word 'bokning' appears in the detail page. If detection fails on a Förfrågan (e.g. encoding issue with 'ö'), the agent would treat it as a Bokning and attempt Hanterad confirmation. Add a positive check and log a warning when defaulting without any matching keyword.
- **SMS failure still marks booking as seen, permanently suppressing retry** (`agent.py`, impact: medium) — In agent.py, when send_sms fails the booking_id is added to seen_ids before continuing. This means a transient 46elks outage permanently prevents that booking's SMS from ever being retried on the next run — the owner silently never gets notified. Do not add failed bookings to seen_ids so they are retried next run.

Claude proposed **7** change(s).

## ✅ Applied (in this PR)
- **Login success wait uses networkidle which can hang on SPA portals** (`portal_scraper.py`, impact: medium) — In fetch_bookings the login flow calls page.wait_for_load_state('networkidle') without a timeout after page.goto, then again with timeout. The first unbounded 'networkidle' wait on a SPA that keeps polling can block indefinitely, appearing as a silent hang (would explain runs where the browser opens but nothing is logged after 'Logging in ...'). Add a bounded timeout to the initial wait.
- **mark_booking_handled login wait_for_url too loose** (`portal_scraper.py`, impact: medium) — mark_booking_handled waits for url != PORTAL_LOGIN_URL, but PORTAL_LOGIN_URL is 'https://.../'. Many redirects keep the same trailing slash briefly or the SPA rewrites hash, so this predicate may resolve immediately or never. fetch_bookings uses the stricter 'promeisterportal.com in url and url != PORTAL_LOGIN_URL'. Make the two consistent to avoid Hanterad running before login completes.
- **qty column index assumption may be wrong in spec parsing** (`portal_scraper.py`, impact: medium) — _extract_specification reads qty = cells[3] unconditionally when len(cells) > 3. The SMS builder only appends ' x{qty}' when qty and qty != '1'. If cells[3] is actually a price or unit column in some table layouts, SMS could show wrong quantities like 'Motorolja x270' (a price). Guard qty to numeric-only values.

## ⚠️ Proposed but NOT applied (review manually)
- **Duplicate SMS suppression across intraday runs causes missed notifications** (`agent.py`, replace_function) — Run history shows repeated 'bookings_found: N, sms_sent: 0' patterns (e.g. 2026-09-15 14:33 found 2 sent 1, then 18:35 found 2 sent 0; 2026-09-16 three runs found 2 sent 0). Because seen_ids persist, a booking that was SMS'd stays 'seen'. That is correct behaviour, BUT Förfrågan/Offert bookings that never got a Hanterad click are re-logged as PENDING every run and never re-notified. The real issue: on the very FIRST detection, if a Förfrågan/Offert booking is added to seen_ids after SMS but no parts/quote action happens, the owner has no way to know it still needs manual work beyond a warning log nobody reads. This is a behaviour concern to review, not an auto-fix.
- **Mismatch: SKILL.md and agent.py describe parts_agent/email_agent but files are missing** (`parts_agent.py`, replace_file) — SKILL.md and agent.py docstrings describe parts_agent.py and email_agent.py as active components (Förfrågan flow launches parts_agent.py; email_agent.py runs every 30 min). Both files report '(FILE NOT FOUND — may need to be created)'. Any code path that imports or subprocess-calls them will crash. This needs human confirmation of intended architecture before creating stubs.
- **SMS builder crashes if qty is non-string** (`agent.py`, replace_function) — In build_sms, qty comes from booking dict and is concatenated with ' x' + qty. If any future extractor returns an int qty, this raises TypeError. Coerce to str defensively.
- **email_trigger import happens inside run() and could hard-crash the agent** (`agent.py`, replace_function) — agent.py does 'from email_trigger import should_run' inside run(). If email_trigger.py is missing (like parts_agent.py and email_agent.py are), the whole booking agent crashes before any booking is processed. Wrap in a try/except and default to running when the trigger module is unavailable.

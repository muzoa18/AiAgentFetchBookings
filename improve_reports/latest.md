# Weekly improve report — 2026-10-12 14:15

Claude proposed **4** change(s).

## ✅ Applied (in this PR)
- **Booking agent finds 0 bookings on every run — Nya tab click likely not loading rows** (`portal_scraper.py`, impact: high) — All 50 logged runs show bookings_found: 0, every single run for over three weeks. This strongly suggests the Nya tab click via JS text-match (/^Nya\b/) is either clicking the wrong element or the booking rows load asynchronously and _collect_booking_links runs before they appear. The current code only waits a fixed page.wait_for_timeout(2000) after the Nya click with no explicit wait for BookingInfo anchors. Adding an explicit wait_for_selector for the anchors (with graceful fallback) makes 0-results a real signal rather than a race condition.
- **Login success not verified — silent login failure would yield 0 bookings** (`portal_scraper.py`, impact: high) — In fetch_bookings, after _fill_login the code only waits for a URL change with timeout then swallows PWTimeout with 'pass'. If login silently fails (wrong field, captcha, session expired) the agent proceeds to scrape a logged-out page and logs 0 bookings — exactly the pattern seen in all 50 runs. Adding a check that we are NOT still on the login page gives a clear error instead of a misleading 0.
- **qty column index assumption may put price into qty field** (`portal_scraper.py`, impact: medium) — In _extract_specification, qty is read from cells[3] unconditionally (cells[3].inner_text()). Table column order on the Specifikation table is not guaranteed to have quantity at index 3 — it could be price or an empty formatting cell, producing wrong 'x' multipliers in the SMS. Guarding qty to only accept short numeric values avoids polluting the SMS with prices or garbage.
- **Timeout branch in fetch_bookings logs no run summary** (`portal_scraper.py`, impact: low) — If a PWTimeout or Exception occurs in fetch_bookings, the function returns whatever bookings were collected (often empty) but the top-level try/except branches do not screenshot the login/table state consistently and no distinct marker is logged. Adding a clear log line at the timeout handler helps distinguish a genuine empty Nya tab from a scraping failure when reviewing the uniform 0-results history.
